# Familiar v3 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:**
- Turn Claude Puppet into **Familiar**: a Claude Code–only companion.
- It pops in while a session is active and starts at login.
- It ships nine mascots.

**Architecture:**
- **Presence** is pure TypeScript next to the mood reducer. The overlay works out whether to show the mascot and tells Rust through a new `set_shown` command, so the hover watch idles while the mascot is hidden.
- **Desktop detection** is deleted end to end.
- **Mascots** stay data files. The renderer gains an optional per-mascot effects hook for signature details.

**Tech Stack:** Tauri 2 (Rust), TypeScript + Vite, vitest, `cargo test`, `tauri-plugin-autostart` v2.

**Spec:** `docs/superpowers/specs/2026-11-17-familiar-v3-design.md` (read it; its "Calls made after the builder check" section is binding).

## Global Constraints
- Idle power: average CPU ≤ **0.3%** and energy ≤ **0.5** over 30 s (app plus web view helpers), visible-idle and hidden.
- Keep the `~/.claude-mascot` folder, port `47653`, and hook recognition by the `/.claude-mascot/hook.sh` path.
- Product name **Familiar**; bundle id `com.familiar.desktop`; port override env var `FAMILIAR_PORT` (no `CLAUDE_PUPPET_PORT` fallback).
- No Claude Desktop chat detection of any kind.
- Never push, publish or create a GitHub repo. Never modify the real `~/.claude/settings.json` in tests; use a temporary HOME.
- No new timers for animation; signature effects use the renderer's frame counter `f`.
- Commit messages end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus
1. **Long tool run.** A session whose last event was `PreToolUse` 20 minutes ago stays present; at 30 minutes it goes. (Task 2 test `working session stays present up to 30 min`.)
2. **App started mid-session.** The first event seen for a session is `PreToolUse` or `Stop`, not `SessionStart`, and it must still create a present session. (Task 2 test `any event creates a session`.)
3. **Status-line refresh never extends presence.** Otherwise `refreshInterval` keeps an idle terminal present forever. (Task 2 test `status updates do not keep a session present`.)
4. **Not connected, or a port error.** The mascot must stay visible, or a new user never sees "Click me to connect". (Task 3 test `shows while not connected` and `shows a server error`.)
5. **Old settings file** with `autoHide` and no login marker loads without losing other fields. Open at login turns on exactly once. (Task 4 test `first run enables login once`.)

### Task 2: Presence rules

**Files:**
- Modify: `src/mood/config.ts` (add `PRESENT_IDLE_MS = 300_000`, `PRESENT_WORKING_MS = 1_800_000`)
- Modify: `src/mood/reducer.ts` (session tracking; `nextDeadline`)
- Create: `src/mood/presence.ts`, `src/mood/presence.test.ts`

**Interfaces:**
- Consumes: `MascotState` from Task 1.
- Produces:
  - `isPresent(s: MascotState, now: number): boolean`.
  - `presenceDeadline(s: MascotState, now: number): number | undefined`, the next time `isPresent` could flip from true to false.
  - `nextDeadline` includes `presenceDeadline`.

Rules, from spec §2 and the builder-check call:
- **Creating a session:** every non-`status` event with a session id creates the session if it's missing (`working: false` unless the event is `prompt` or `tool`) and sets `lastEventAt`. `session_start` now creates the session too.
- **Ending presence:** `session_end` deletes the session.
- **Present:** a session is present when either holds:
  - `!working && now - lastEventAt < PRESENT_IDLE_MS`;
  - `working && now - lastEventAt < PRESENT_WORKING_MS`.
- `status` events never touch `lastEventAt`.

- [ ] **Step 1: Write failing tests** in `presence.test.ts`:
  - `no sessions → not present`
  - `session_start makes it present`
  - `any event creates a session`: a `stop` for an unseen id makes it present.
  - `session_end of the last session → not present`
  - `idle session leaves after 5 min`: present at +299_999 ms, not present at +300_000 ms after the `stop`.
  - `working session stays present up to 30 min`: a `tool` at t, present at t+1_799_999, not present at t+1_800_000.
  - `status updates do not keep a session present`: a `stop` at t, then `status` events every 10 s, gives not present at t+300_000.
  - `two sessions: present while either is`
  - `presenceDeadline returns the earliest leave time`
  - `nextDeadline includes the presence deadline`
- [ ] **Step 2:** Run `npx vitest run src/mood/presence.test.ts`. Expected: FAIL (module missing).
- [ ] **Step 3:** Implement `presence.ts` and the reducer's session tracking. The mood logic keeps using `SESSION_STALE_MS` for working-mood staleness, unchanged.
- [ ] **Step 4:** Run `npx vitest run src/mood`. Expected: PASS, including the existing reducer tests.
- [ ] **Step 5:** Commit `feat: session presence rules`.

### Task 3: Show only while present

**Files:**
- Create: `src/ui/visibility.ts`, `src/ui/visibility.test.ts`
- Modify: `src/ui/overlay.ts`, `src-tauri/src/lib.rs`, `src-tauri/src/settings.rs`, `src/settings/settings.ts`, `settings.html`

**Interfaces:**
- Consumes: `isPresent` (Task 2).
- Produces:
  - `shouldShow(v: { hidden: boolean; connected: boolean; present: boolean; settingsOpen: boolean; noticeActive: boolean; serverError: boolean }): boolean`. It returns `!hidden && (!connected || serverError || present || settingsOpen || noticeActive)`.
  - Rust command `set_shown(shown: bool)`, which stores into `struct Shown(AtomicBool)`.
  - Rust event `mascot-settings-open` with a `bool` payload, emitted when the Settings window opens and when it is destroyed.

Behaviour:
- The overlay recomputes `shown` in `render()`.
- **On false→true:** `ember.setVisible(true)` and then `popIn()`.
- **On true→false:** `popOut()`, then after 300 ms (the pop-out length) set the stage to `gone` and call `setVisible(false)`.
- **Every change:** call `invoke("set_shown", …)`.
- **Hover watch:** uses `!shown` where it used `s.hidden` today.
- **After a successful Connect:** the notice text is exactly "I'll pop up when you start Claude Code." for `NOTICE_MS`.
- **Initial state:** `connected` is fetched once at startup and set to true after `mascot_install` succeeds (false after uninstall, via the existing `mascot-settings` refresh or a re-query).
- **Removed:** the `autoHide` setting goes from Rust (`Settings.auto_hide`, `SettingsPatch.auto_hide`, the tray "Hide while asleep" item, the `"auto-hide"` menu arm), from the overlay and from Settings. A file containing `"autoHide": true` still loads.
